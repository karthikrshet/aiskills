# Skill Authoring Guide

This guide explains how to author a new engineering skill for the AISkills library.

---

## 1. Skill Philosophy

An AISkills skill is a **structured engineering workflow** for an AI coding agent — not a prompt, code snippet, or ad-hoc checklist.

A high-quality skill:
- Solves a specific, bounded engineering problem.
- Has clear preconditions and explicit inputs.
- Decomposes work into reproducible steps with defined outputs.
- Specifies decision points where the agent must stop or consult a human.
- Enforces strict safety constraints.
- Provides testable validation checks.

---

## 2. Directory Structure

Place your skill in the appropriate category under `skills/`:

```text
skills/<category>/<skill-name>/
├── SKILL.md          # Required canonical skill definition
├── references/       # Optional supplementary documentation
└── examples/         # Optional domain-specific worked examples
```

The directory name must match the `name` field in the frontmatter.

---

## 3. Frontmatter Specification

Every `SKILL.md` must start with YAML frontmatter bounded by `---`:

```yaml
---
name: your-skill-name
description: |
  Clear, concise description of when and why an agent should activate this skill.
version: "0.1.0"
category: discovery | requirements | architecture | implementation | testing | debugging | code-review | ai/rag | ai/agent-design | ai/evaluation | ai/context-engineering | ai/ai-security | ai/production-ai
tags: [tag1, tag2, tag3]
risk: low | medium | high
status: experimental | alpha | beta | stable
related-skills:
  - related-skill-name
---
```

---

## 4. Required Markdown Sections

Your skill body must contain all 13 canonical sections in order:

```markdown
# Skill Title

## Purpose
What engineering problem does this solve and why is a structured skill necessary?

## When to Use
Specific triggers and conditions for activation.

## When Not to Use
Scenarios where another approach or skill is appropriate.

## Inputs
Table of required and optional inputs.

## Preconditions
Checklist of requirements that must be met before starting.

## Workflow
Step-by-step methodology. Each step specifies what to inspect and what to produce.

## Decision Points
Conditions where the agent must inform, consult, or request human approval.

## Safety Constraints
Non-negotiable rules the agent must never violate.

## Expected Output
Artifacts and deliverables generated by the skill.

## Validation
Checklist to verify the skill was executed correctly.

## Failure Handling
Table mapping failure modes to recovery actions.

## Examples
Realistic worked example showing inputs, actions, and outputs.

## Related Skills
Links to predecessor, successor, or complementary skills.
```

---

## 5. Validation and Testing

Before submitting a new skill:

1. Run the validator:
   ```bash
   aiskills validate
   ```
2. Check repository health:
   ```bash
   aiskills doctor
   ```
3. Run the automated test suite:
   ```bash
   pytest tests/
   ```
